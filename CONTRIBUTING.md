# Contributing to SolarSage

See the [development guide](https://bballdavis.github.io/SolarSage/development/) for environment setup, checks, documentation, and compatibility requirements.

Use issues for reproducible bugs and focused feature proposals. Explain the expected behavior, actual behavior, Home Assistant/SolarSage versions, and relevant sanitized evidence. Keep household recordings, tokens, VINs, location data, private keys and local workspace files out of commits and attachments.

For control changes, add meaningful tests against fake systems. Preserve shadow/dry-run defaults and schedule ownership/recovery guarantees. Run lint, formatting, the Python suite, and the documentation build before submitting a pull request.
